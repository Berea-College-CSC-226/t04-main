2.f. Define Each Term:
```
        a. Clone:       Creating a copy of the main repository.

        b. Commit:      Saving of local changes.

        c. Push:        Updating local changes to the cloud.

        d. Branch:      Separate versions of a coding project meant to be used as scratchboards to make and test code before implementing into the original and final form of the project. (The original form of the project can also count as the "main" branch."

        e. Pull:        The request of an updated version of the project to be added to the current branch worked upon. Aka, when progress is made on one form of the project (i.e. Github or another branch), you can "pull" the progress to another form of the project. This typically works on a local setting.

        f. Pull Request:This is a form of the pull but independently made to be the actual MERGING of the code to its original and main form (i.e. the work made on a personal branch is requested to be pulled and merged onto the main branch). This is typically between local and cloud settings.

        g. Merge:       The integration of code from one branch into another (i.e. from an individual's branch into the main branch in the form of an approved pull request).

        h. Remote:      This is the equivalent of the word "cloud;" refers to the presence of data on the internet (to be accessed by differing computers). 

        i. Local:       This is the opposite of "remote," existing to be accessed only by a single computer as it remains in internal storage.

        j. Fetch:       Does half the work of a pull request by dragging code from the remote form to the local form, requiring a merge to complete the process. A pull request drags the code and auto-merges.

    Check your definitions against the [git glossary](https://help.github.com/articles/github-glossary/) 
    to ensure they are correct.
```
